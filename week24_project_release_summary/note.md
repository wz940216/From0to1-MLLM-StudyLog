# week24_project_release_summary

写到第 24 周，心里会有一点停下来的感觉。

这个仓库一开始只是想记录自己怎么从零学习多模态大模型。刚开始关心的事情很具体：环境能不能装好，模型能不能下载下来，显卡能不能跑起来，脚本会不会一启动就报错。现在回头看，23 周已经留下了很多东西：代码、截图、笔记、实验、报错、修修补补的脚本，还有一些当时觉得很麻烦、后来发现很有用的总结。

第 24 周就不再硬写一篇技术文章了。前面已经写了足够多的技术细节，这一周更适合慢一点，把前 23 周重新走一遍，认真和这段学习告个别，然后开始下一段新的学习旅程。

## 起点

最开始的几周，其实就是想先把东西跑起来。

week01 做环境搭建。Conda、CUDA、PyTorch、Transformers，一个个装，一个个试。很多 AI 工程学习就是这样开始的。先确认 `torch.cuda.is_available()` 能返回 True，再去看更复杂的模型结构。环境通了，后面才有机会继续折腾。

week02 进入 SFT、LoRA、QLoRA。那时候对微调的理解还很粗，只知道完整训练一个大模型不现实，所以要学参数高效微调。真正跑过之后才明白，LoRA 的意义除了省参数，还在于它给普通机器上的实验留出了空间。QLoRA 又把显存压力往下压了一层，让一些原本看起来很远的训练流程变得可以尝试。

week03 跑通 LLaVA demo，第一次把图片和问题一起送进模型。这个体验很直接：原来图片需要先经过视觉编码器，再通过 projector 接到语言模型的表示空间里。以前看架构图觉得抽象，跑过推理脚本以后，数据流就清楚了很多。

week04 做 CLIP 检索和零样本分类。CLIP 这一周很重要，因为它把图文对齐讲得很干净：图片和文本各自编码，放到同一个向量空间里，匹配的靠近，不匹配的拉远。后面再看很多多模态模型，都会发现这个对齐思想一直在背后。

## 第一个小应用

week05 和 week06 开始从模型脚本走向小应用。

BLIP 和 BLIP-2 让图像描述这件事更具体。CLIP 更擅长判断图文是否相似，BLIP 更擅长把图像内容说出来。到了 week06，把 CLIP 检索和 BLIP caption 放进 Web demo 里，学习的感觉开始变了。

以前只要脚本能输出一行文字，就算跑通。做成 Web demo 以后，还要考虑上传图片、等待时间、结果展示、图片列表、embedding 缓存、用户怎么点、页面是否直观。模型能力只是其中一部分，真正给人用的时候，体验会把很多隐藏问题暴露出来。

这也是第一次明显感觉到，学习多模态不能一直停在单个模型调用上。哪怕只是一个很小的 demo，也已经有了系统的影子。

## mini-LLaVA

week07 到 week12 是整个学习里最扎实的一段。

这一段开始自己搭 mini-LLaVA。视觉编码器、语言模型、projector、配置文件、数据集、训练脚本、推理脚本，每一块都要自己接起来。刚开始代码肯定粗糙，但粗糙也有价值，因为只有自己接过，才知道每个模块之间到底靠什么连在一起。

以前说视觉 token 接入 LLM，可能只是一句话。自己写的时候会遇到很多具体问题：图像特征 shape 是多少，projector 输出维度要不要对齐 hidden size，`<image>` 放在哪里，answer 的 loss 怎么 mask，哪些参数冻结，哪些参数训练，batch 里图像和文本怎么配对。

week08 跑第一版训练，week09 做重构和测试，week10 做多任务数据，week11 支持多轮对话，week12 再把工程文档整理一遍。这几周最有价值的地方，是自己真的把一个多模态训练工程拆开看了一遍。

那段时间留下了几条很实在的经验：

- 数据格式比想象中更重要。
- shape 测试很小，但能省很多排查时间。
- forward 能跑通，只说明代码能走完，不代表训练一定有效。
- 推理脚本能用，不代表工程可以长期复用。
- README 越早写，后面越不容易把自己绕进去。

## 学会管住输出

week13 到 week16，开始关心模型怎么回答。

前面更多是在想模型能不能回答，这一段开始在意回答格式、上下文、安全边界和失败处理。Chat 格式、system/user/assistant、多轮对话、结构化输出、JSON 解析、安全过滤，这些内容看起来没有模型结构那么显眼，但做应用时很重要。

跑多轮对话时会发现，模型可能忘记前面看过的图片，也可能把上下文混在一起。要求它输出 JSON，它可能少一个括号，也可能多说几句解释。做安全过滤时又会发现，不能只指望模型自己判断边界，工程上也要有输入和输出的保护。

这几周让我慢慢接受一件事：模型输出需要被管理。Prompt、模板、解析器、重试、安全规则、数据格式，这些都在帮模型把能力落到更稳定的行为上。

week16 做阶段总结时，整个学习已经从训练模型往模型行为管理靠近了一步。

## 服务和部署

week17 到 week20，学习重点转向推理和服务。

vLLM、KV cache、prefill、decoding、并发、延迟、QPS、FastAPI、限流、日志、压测，这些内容刚开始看起来有点偏后端。但模型真正作为服务运行时，这些问题都会出现。

模型在本地脚本里跑通，只说明它能回答一次。放进服务以后，就要面对启动时间、显存占用、并发排队、请求超时、错误返回、日志排查和性能指标。没有这些东西，demo 很难往真实应用再走一步。

week19 把多模态问答封成服务，week20 做压测和优化。到了这里，对部署的理解也变了。部署不能只放在训练结束后收尾，它本身就是模型工程的一部分。模型能力要能被稳定调用、观察和维护，才算真正有用。

## 最后一个项目

week21 到 week23 做了文档多模态问答系统。

选文档问答作为最后项目很自然。文档里有文字、版面、表格、图片和页码，很适合检验多模态理解，也很容易暴露工程问题。week21 做需求和路线，week22 跑通 alpha，week23 做缓存、耗时统计、Prompt 类型、错误结构、日志、测试和压测。

回头看，这个项目更像一个出口。前面学过的模型、数据、Prompt、服务、日志、测试、性能优化，都在这里汇到一起。它没有必要承载这 24 周的全部意义，但它确实证明了前面的学习没有散掉，最后能落到一个具体系统里。

这个项目也提醒我，真实工程里很多重要工作都很朴素。缓存、日志、错误结构、耗时统计、smoke test、benchmark，这些东西单独看都不惊艳，但少了它们，系统就很难反复调试和继续迭代。

## 这 23 周留下的东西

如果只列技术名词，这 23 周能列很多：Transformers、LoRA、QLoRA、CLIP、BLIP、BLIP-2、LLaVA、mini-LLaVA、Chat SFT、DPO、vLLM、FastAPI、OCR、Qwen3-VL。

但真正留下来的，更多是一些能力和习惯。

第一，是把复杂系统拆小的能力。

刚开始看多模态大模型，会觉得它是一个很大的整体。后来慢慢拆开，才知道里面有视觉编码、模态对齐、语言生成、数据格式、训练策略、推理服务和前端交互。每一层都有自己的问题，也都有自己的检查方法。

第二，是从脚本思维慢慢走到工程思维。

脚本能跑一次很重要，但后面还要关心配置、日志、缓存、测试、文档和性能。week23 做的很多事情并不复杂，却让项目更容易继续维护。

第三，是排查问题时更有顺序。

模型答错时，不急着换模型。先看数据有没有问题，再看 prompt、上下文、页面选择、OCR 结果、输出约束。沿着链路查，比凭感觉改参数可靠得多。

第四，是接受学习过程里一定会有粗糙的地方。

有些实验只是短训练，有些代码只是最小可用，有些结果也没有很好看。这 24 周最重要的地方，是每一步都让下一步更清楚。

## 那些坑

这段学习里踩过很多坑。

环境问题最早出现，也最容易反复。CUDA、PyTorch、bitsandbytes、vLLM、PaddleOCR、大模型权重，只要版本不合适，链路就可能断掉。

数据问题也很明显。多模态训练不能只把图片路径和文本拼起来，`<image>` 标记、对话轮次、answer mask、system prompt、任务混合比例，都会影响训练。

显存问题贯穿了整个过程。4bit、8bit、LoRA、max images、max tokens、batch size、KV cache，很多参数一开始是为了让实验先跑起来，后面才慢慢变成优化手段。

Prompt 问题到了后期更明显。提示词写得长，不一定更稳。不同任务混在一个提示里，模型很容易在总结、表格、标题定位之间混用回答方式。

工程问题最后集中出现。没有日志就不知道失败在哪里，没有缓存就要重复等待，没有测试就不敢改，没有压测就不知道系统边界。

这些坑也算是这段学习的一部分。它们把很多概念从纸面带到了真实代码里。

## 好好告别

这个仓库的名字是 `From0to1-MM-LLMs-StudyLog`。现在看，这个名字挺合适。

它算不上完美项目，也算不上一套课程。它记录的是一段慢慢熟悉多模态大模型的过程：从第一条推理脚本，到第一个 LoRA 训练；从 CLIP 检索，到 BLIP caption；从调用 LLaVA，到亲手搭 mini-LLaVA；从训练脚本，到服务部署；最后落到一个文档问答系统。

第 24 周不需要再往里面塞新功能了。它更适合停下来，承认这段学习已经完成了它该完成的任务。

过去 23 周证明了一件很简单的事：只要路线连续，每周往前推一点，半年后就会和刚开始不一样。以前只会跑 demo，现在至少能拆系统、写训练、做服务、查问题，也知道一个多模态应用从想法到落地中间会经过哪些环节。

所以这一周，就把它当作一个认真收尾。

谢谢这 24 周里那些跑通的脚本，也谢谢那些没有一次成功的报错。它们一起把这段路铺出来了。

## 下一段旅程

下一段不用再从零开始，可以带着这 24 周积累下来的经验继续往前走。

我想把后面的学习放在三个方向上。

第一，继续做更可靠的文档智能。

文档问答还可以继续往前走。接下来可以重点做检索、引用和可信度，比如 BM25、embedding、reranker、证据片段、页码校验、结构化答案和可点击引用。目标很简单：回答问题时能说清楚依据在哪里。

第二，更认真地做模型训练。

mini-LLaVA 已经搭过一版，后面可以把训练做得更系统：数据质量、训练日志、评估集、loss 曲线、消融实验、模型对比，都可以补起来。重点可以少放在追更大的模型上，多放在把实验做清楚、做可复现上。

第三，做更贴近真实使用的多模态应用。

可以继续选一个垂直场景，比如论文阅读助手、财报问答、表格理解、UI 理解、医学文档预审或者工业报告分析。下一次除了复现方法，也尽量做一个能被反复使用的小系统。

这 24 周到这里结束。下一段学习，从一个更清楚的问题开始，慢慢往前做。
